Guide to developing your Occupational Safety and Health (OSH) AI assistant.

To develop your Occupational Safety and Health (OSH) AI assistant using Antigravity or any AI-assisted coding platform, you should first understand that you are not “training” a new AI model from scratch. Instead, you will build a Retrieval-Augmented Generation (RAG) application, where a powerful Large Language Model (LLM) such as GPT reads and answers questions from your uploaded PDF documents. The overall system works by extracting text from your OSH PDFs, splitting the content into smaller chunks, converting those chunks into numerical embeddings using an embedding model, storing them in a vector database, and then retrieving the most relevant chunks whenever a user asks a question. These retrieved chunks are then sent along with the user’s query to the LLM, which generates an answer grounded in your documents. This approach is significantly easier, cheaper, faster, and more accurate for document-based question answering than attempting to fine-tune an LLM.

Begin by installing Python, VS Code, and Git on your computer. Create a project folder such as “OSH_AI_ASSISTANT” and inside it create a “data” folder where you will place all your PDFs, such as DGFASLI manuals, heat stress guidelines, occupational disease references, Factory Act documents, AFIH notes, or any OSH-related material. Then create a Python virtual environment and install the required libraries including Streamlit, LangChain, ChromaDB, PyPDF, sentence-transformers, OpenAI, and tiktoken. After that, create an OpenAI account through OpenAI Platform, add billing, and generate an API key that will allow your application to access GPT models and embedding services. Your app will use this API key to communicate with the LLM.

The next stage is document ingestion and vector database creation. Create a Python script that reads all PDFs from the “data” folder using PyPDFLoader from LangChain. The script should extract the text from each page and split it into smaller chunks using a RecursiveCharacterTextSplitter, typically with chunk sizes around 500 characters and some overlap between chunks to preserve context. Then use an embedding model such as “sentence-transformers/all-MiniLM-L6-v2” or OpenAI embeddings to convert these chunks into vectors. Store the vectors inside a vector database such as ChromaDB or Qdrant. This database becomes the searchable knowledge base of your AI assistant. When users later ask questions, the application performs similarity search on this vector database to retrieve the most relevant text passages from your documents.

Once the database is prepared, build the web application layer. The easiest beginner-friendly frontend is Streamlit because it allows you to create a functional chatbot interface with minimal coding. Create a main application file where the Streamlit UI displays a title, a text input box for user questions, and a button to submit queries. When the user asks a question, your app should query the vector database using similarity search to retrieve the top matching chunks from the PDFs. These retrieved passages are combined into a context prompt that is sent to the OpenAI GPT model through the API. The prompt should instruct the model to answer only from the provided OSH context and avoid hallucinating information outside the documents. The model’s response is then displayed back to the user in the Streamlit interface. You should also display metadata such as PDF name and page number so users can verify the source of the answer, which is particularly important in occupational health and regulatory applications.

After confirming that the system works locally, the next step is deployment so that anyone can use the assistant online. Create a GitHub repository using GitHub and upload your entire project including the application code, requirements.txt file, and database generation scripts. Then use a cloud hosting platform such as Render, Railway, or Hugging Face Spaces to deploy the application. Connect the hosting platform to your GitHub repository, specify the build command to install dependencies from requirements.txt, and configure the start command to run the Streamlit app. Add your OpenAI API key as an environment variable rather than hardcoding it into the application for security. Once deployed, the platform will generate a public URL where users can access your OSH AI assistant from any browser.

As your system matures, you can gradually add advanced features such as user authentication, multilingual support for Hindi and Bengali, conversational memory, PDF upload functionality for administrators, voice interaction, citation highlighting, analytics dashboards, and integration with your existing occupational health projects such as smart helmets, heat stress monitoring, and digital twin systems. You can also integrate specialized knowledge from DGFASLI, ILO, OSHA, Factory Act regulations, pneumoconiosis manuals, and AFIH training materials to create a highly specialized OSH knowledge platform. Initially, however, your primary goal should be to build a stable and accurate RAG-based application rather than attempting fine-tuning or custom model training. This architecture is already used by many professional AI document assistants because it is scalable, maintainable, and highly effective for domain-specific question answering.
